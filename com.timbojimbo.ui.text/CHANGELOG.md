## [Unreleased]

### Added

- `TextBlock`: a `MaskableGraphic` that lays out and shapes its text with Unity's Advanced Text Generator (the engine behind UI Toolkit's advanced text) and draws the result as UGUI geometry. HarfBuzz shaping, ICU line breaking and bidi, OS font fallback and colour emoji, with no native plugins and no bundled fonts. The root draws nothing itself; it owns three children in draw order: decoration prefabs, the glyph renderer (one sub-mesh and material per atlas texture) and inline-object prefabs
- `TextLayout`: the layout behind a text as a plain class, usable without a component. It parses the source, builds the layout text, generates, and answers queries: size, character rectangles by source range, link hit testing, and the prefab placements a theme asks for. `TextBlock` feeds it a rect and turns the result into UGUI. Measuring is re-entrant, since a handler may measure its own label
- Text, font size, alignment, word wrap, overflow (TextMeshPro-style overflow, ellipsis or truncate), max lines, base direction, character/word/paragraph spacing, bold, italic, underline and strikethrough. Colour comes from `Graphic.color` and is applied at mesh build, so tinting never re-shapes the text
- `FontStack`, the one font reference the package uses: an ordered list of fonts, each an installed OS family, a TTF/OTF in the project (Google Fonts drop straight in) or a dynamic `FontAsset`. The first source that resolves is the primary font, so a stack can list per-platform families; the rest are the fallback chain. An OS Fallbacks toggle, on by default, appends the fonts the OS names for missing glyphs. A stack with no sources is the OS default font, which is what texts without a stack use. OS families are probed for Bold, Italic and Bold Italic faces, font files can name theirs, and the OS default font gets its real faces too; without a real face the engine synthesises bold and italic, and each source's Synthetic Bold slider sets how heavy that bold is
- `TextBlockSettings`: project-wide defaults (font stack, theme) from a Resources asset
- `ILayoutElement` support (preferred width and height) so ContentSizeFitter and layout groups size texts, plus `TextBlock.Measure` for measuring without a component, e.g. row heights for virtualised lists
- Markdown dialect for chat and UI text: `**bold**`, `*italic*`, `__underline__`, `~~strike~~`, `` `code` ``, `[label](url)`, bare URLs, backslash escapes, `#`/`##`/`###` headings, `-` and `1.` lists, `>` quotes and fenced code blocks. A newline is a line break. No HTML, images or tables. The parser only classifies the source and records source indices (`TextDocument`); `LayoutText` builds the text the engine lays out, inserting line breaks, indents, list markers, layout padding and object placeholders, and maps indices between source and layout both ways. `TextTheme` sets heading scales, link and quote colours, the code font stack and the inline handlers
- Links: `OnLinkClicked` UnityEvent and `LinkClicked` C# event with the href, hit-tested by the generator
- Inline handlers (`InlineHandler` assets on a theme): declare a trigger (delimited like `:emote:` or a prefix like `@name`) and either style the matched text and place a prefab behind each line fragment of it (`Fragments`), place one prefab across the full width of every line it touches (`Block`), or replace it with a box that never splits and place a prefab over it (`Atomic`), centred on the text unless the request sets how much sits above the baseline. `PrefabInlineHandler` covers the no-code cases; `Accepts` lets a subclass decline a match so `10:30:45` stays text; `PaddingEm` asks for layout padding either side of the text, which moves the surrounding text over like CSS padding on an inline element and stays at the start and end of a span that wraps. Prefab roots implement `IInlineContent` to receive the token, context and fragment; instances are pooled
- `` `code` `` spans and fenced code blocks get a rounded `Box` background with a border, rounding only the outer corners of a span that wraps. Horizontal padding is layout, vertical padding is drawn over the line gap
- `ITextBlockGlyphModifier`: components on the same object alter glyph geometry as it is built, for per-glyph effects
- `TextBlock.GetCharacterRects` for the rectangles a source character range covers
- Each `TextBlock` holds a hidden reference to the engine's built-in ICU data asset (`icudt73l.bytes`), assigned automatically in the editor, so player builds carry the line-breaking, bidi and emoji-sequence data the generator needs
- Inspector for `TextBlock` and a `FontSource` drawer that shows only the fields for its kind
- Chat sample (Package Manager > Samples): a message feed scene with a theme, an emote set handler, a mention chip handler with a nested `TextBlock`, and a monospace font stack for code
- Tests: the Markdown parser, the layout text and its mapping, and the engine behaviours the bridge relies on (padding units, sprite boxes, no-break-space padding, real and synthetic bold, range rectangles, link hit testing)
- The generator's managed API is internal to Unity. The `UnityEngine.TextCore.Tools` assembly (`Runtime/Bridge`) borrows a name the TextCore module grants `InternalsVisibleTo` access to and wraps everything behind a public API; nothing else in the package touches Unity internals
